# GPT Image 2 через Zapro: настройка личного кабинета

В [каталоге Zapro](https://po.zapro.su/pricing) есть `gpt-image-2`.
В [инструкции провайдера](https://po.zapro.su/docs/api/#генерация-изображений)
описаны генерация и редактирование прикреплённых изображений. Публичный адаптер
Provider Image из опубликованного установщика также использует `/v1/images/edits`
с несколькими файлами `image[]`; установщик прочитан как текст, не запускался.
Наш адаптер использует `https://po.zapro.su/v1/images/edits` и запрашивает
`response_format=b64_json`. Поддержка референсов подтверждается документацией и
кодом провайдера; первый реальный запрос нужен для проверки конкретного ключа и
доступного маршрута. Мы не выдаём офлайн-тест за успешную платную генерацию.

## 1. Подготовить приложение

После обновления кода перезапустите backend и обновите страницу. При запуске
создастся новая таблица `user_image_settings`. Существующие колонки и данные
не изменяются. Во время разработки рабочая БД и бот не запускались.

Серверу нужен рабочий `ENCRYPTION_KEY` в `.env` для шифрования личных ключей.
Если он уже настроен, сохраняйте его прежнее значение: замена делает старые
зашифрованные данные нечитаемыми. Только если ключа ещё нет, сгенерируйте его:

```powershell
.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Добавьте полученное значение в `ENCRYPTION_KEY` и перезапустите backend.
Ключ Zapro не нужно записывать в `.env`, менять общий текстовый AI-провайдер
или настройки Codex. `OPENAI_IMAGE_ENABLED=true` для личного ключа не требуется.

## 2. Создать ключ Zapro

1. Войдите в свой кабинет [Zapro → API-ключи](https://po.zapro.su/keys).
2. Создайте ключ с группой **AUTO** — эту группу рекомендует провайдер.
3. Если включён фильтр моделей, разрешите **gpt-image-2**. Проверьте баланс и
   срок действия ключа. При наличии ограничения расходов задайте его у провайдера.
4. Скопируйте полный ключ. Не отправляйте его в чат, не публикуйте и не добавляйте
   в Git.

## 3. Сохранить ключ в Клоннере

1. Откройте **Pro Профиль → Мой API для изображений**. Этот же блок есть на странице
   **Фото по референсам** (`/dashboard/editor`).
2. Выберите **Zapro — po.zapro.su**, вставьте ключ.
3. Отметьте **Включить генерацию с моим ключом**.
4. Для первого теста установите дневной лимит **1** и нажмите **Сохранить API**.
5. Нажмите **Проверить доступ без генерации**. Запрашивается только
   `GET https://po.zapro.su/v1/models`; изображения не создаются. Модель должна
   присутствовать в каталоге именно вашего ключа. Каталог не гарантирует работу
   каждого endpoint.

Ключ хранится зашифрованным в БД, привязан к текущему пользователю и обратно
в браузер не возвращается. Пустое поле при сохранении оставляет прежний ключ
того же провайдера. При смене провайдера требуется его собственный ключ.
Кнопка **Удалить ключ и выключить** убирает сохранённый секрет и отключает генерацию.

## 4. Первая генерация

1. Откройте **Фото по референсам**.
2. Выберите фото нашей взрослой виртуальной модели и **одно** фото сумки.
3. Задайте простую сцену: светлая студия, мягкий свет, спокойная поза, сумка целиком
   видна. Для экономного пилота можно выбрать среднее качество.
4. Нажмите **Создать 1 фото через платный API** и дождитесь результата. По витрине
   средняя задержка модели на дату проверки около 212 секунд; запрос может занять
   несколько минут. Не закрывайте страницу.
5. Сравните цвет, форму, материал, ремень и фурнитуру с оригиналом; проверьте лицо
   и руки. Скачайте пригодный результат и посмотрите реальное списание в Zapro.
6. Затем увеличьте дневной лимит до 5 и выберите пять оригинальных фото расцветок.
   Генератор получает каждое фото вместе с референсом модели, без перекрашивания
   одного результата во все цвета.

Генерация не публикует фото в Telegram автоматически. Загруженные исходники
не перезаписываются; результаты защищены авторизацией владельца.

## Баланс $5 и ограничения пилота

На 04.10.2026 витрина показывает **$0.50 за запрос внутри сервиса** и **$0.06 как
«реальную стоимость»**. Это разные шкалы; по $0.06 нельзя уверенно вычислять число
генераций из показанного в кошельке баланса $5. Если $5 — внутренний баланс и
списывается $0.50, ориентир — 10 запросов; подтвердите это списанием одной пробы.
Не обещаем постоянство цены или количество успешных фото: ошибки/таймауты могут
иметь свою политику списания, а качество проверяется вручную.

Автоматических повторов нет; после ошибки оставшиеся варианты пропускаются.
Повторное получение того же запроса не запускает его заново в пределах 24 часов
одного backend-процесса. Дневной лимит попыток и защита повторов хранятся в памяти:
перезапуск их сбрасывает, несколько workers не координируются. Для пилота нужен
один backend-процесс; это не строгий денежный лимит. При пяти последовательных фото
общий запрос может идти долго. Таймаут reverse proxy должен покрывать весь альбом
или сначала используйте одно фото. Реальная постоянная очередь пока не реализована.

## Фоновый перенос товаров на нашу модель

В «Магазине» и «Парсере» появилась отдельная галочка «Переносить товары на нашу модель через GPT Image 2 в фоне». Без неё работает прежний перенос.

1. Включите галочку, прикрепите 1–3 фото одной взрослой виртуальной модели. Для начала достаточно чёткого анфаса в полный рост. Дополнительные профиль и вид сзади помогают задать внешность для других поз, но одинаковое лицо не гарантируется.
2. В поле «Что продаём» укажите конкретный предмет: например, «кожаная сумка в руке человека; переносим только сумку». В кадре могут быть человек и другие вещи; генератор должен извлечь указанный товар, а внешность взять из нашей модели. Нажмите «Сохранить модель и описание». Настройки хранятся на сервере для вашего аккаунта.
3. Укажите реальные каналы донора и назначения, выберите **1 пост**, отключите живой мониторинг для первой проверки. Лимит фото в профиле должен вмещать весь альбом: 5 исходников требуют 5 попыток. Перед первым автоматическим переносом проверьте новый промпт в ручном разделе «Фото по референсам».
4. Запустите перенос. Сервер загрузит исходный Telegram-альбом, подготовит описание, отправит основной цветовой референс, все остальные фото альбома и ракурсы модели в `/images/edits`. На каждый исходник отдельный результат; другие расцветки не должны менять цвет текущего варианта. Ракурсы одного цвета тоже считаются отдельными исходниками — автоматического объединения одинаковых расцветок пока нет.
5. Весь готовый альбом публикуется в указанные каналы. Для нескольких каналов фото генерируются один раз. Магазин сохраняет наценки, артикулы (если включены) и синхронизацию текста с Mini App. Рерайт использует существующий текстовый API сервера, отдельно от личного ключа изображений.
6. Если включён живой мониторинг, после первоначального импорта сервер опрашивает новые посты донора примерно раз в 30 секунд, с паузой для завершения загрузки альбома. Он работает после закрытия вкладки. При ошибке обработки или нехватке дневного лимита задача останавливается; повторных платных запросов нет. Видео и обычная очистка водяных знаков в этом режиме не запускаются.

Фото модели и результаты хранятся в закрытой папке `private_image_previews`; статус и история задания — в SQLite/Postgres. Результаты доступны вашему аккаунту через авторизованный API. Ошибка одного варианта не публикует неполный альбом; уже готовые фото доступны для скачивания. Остановка запрещает следующий запрос и отправку, но запрос, уже принятый провайдером, мог быть оплачен.

После перезапуска сервера задача помечается прерванной и не продолжается автоматически. Повтор того же ID задания не запускает новые генерации. Неизвестный результат отправки в Telegram блокирует повторную отправку этого товара в тот же канал: сначала нужно проверить канал. Исполнение и ограничение параллельности рассчитаны на один backend-процесс; общий дневной счётчик фото пока остаётся в памяти и сбрасывается при рестарте. Это не постоянная очередь с автоматическим восстановлением и не строгий денежный бюджет.

## Диагностика

- **Ключ не сохранён / ENCRYPTION_KEY:** настройте шифрование сервера, не меняя
  уже существующий ключ шифрования.
- **Модели нет в каталоге:** проверьте группу AUTO, фильтр моделей и права ключа.
- **401/403:** ключ неверен, истёк или не имеет доступа к маршруту.
- **429:** проверьте баланс и лимиты у Zapro.
- **Генерация не выполнена:** проверьте поддержку `/v1/images/edits` для `gpt-image-2`
  у провайдера. Наш адаптер не меняет модель или endpoint автоматически.
- **Таймаут:** сначала проверьте списания и журналы Zapro, затем получите ответ
  того же запроса кнопкой повторного получения. Изменение входов создаёт новый
  платный запрос.

Проверка реализации: 47 офлайн-тестов и строгая TypeScript/Vite-сборка прошли.
Фоновый цикл проверен с временной БД и имитацией Telegram/генератора: альбом,
несколько каналов, остановка, ошибки, лимит, перезапуск, Mini App и новые посты.
Галочка и поля модели проверены в реальном локальном кабинете. Агент платных
запросов не запускал. Пользователь сообщил о первом ручном результате; точность
переноса товара с обновлённым промптом ещё требует реальной проверки.
