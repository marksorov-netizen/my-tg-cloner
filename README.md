# 🤖 MyBot AI — AI Клонер постов и Магазин Telegram

Автоматизированная система клонирования, AI-рерайта и публикации постов из каналов-доноров в целевые Telegram-каналы с умным ценообразованием (Опт / Дроп / Розница) и встроенным ботом для приёма заказов.

---

## 🌟 Основные возможности

- 🚀 **Парсер & Клонер каналов**: Сбор постов с каналов-доноров с сохранением медиа-альбомов (все фото и видео).
- 🧠 **AI-Рерайт**: Умная обработка текстов с сохранением стилистики, удалением чужих ссылок и водяных знаков через Gemini / Zapro AI.
- 💰 **3-Уровневое Ценообразование**: Авто-расчёт наценок (Опт / Дроп / Розница) от максимальной цены донора.
- 📦 **Склад & Артикулы**: Автоматическая генерация артикулов (`ART-0001`), отслеживание остатков и размеров (обувь, одежда).
- 🛍️ **Telegram Order Bot**: Приём заказов в Telegram с мгновенным показом альбома товара, выбором размеров/цвета и отправкой уведомлений менеджеру.
- ⏹️ **Мгновенная остановка задач**: Полный контроль над процессом переноса в один клик.

---

## 🚀 Быстрый запуск на сервере (VPS / Ubuntu / Debian)

### Вариант 1: Запуск через Docker (Рекомендуется)

1. **Клонируйте репозиторий**:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd MyBotAi11-main
   ```

2. **Создайте `.env` из примера**:
   ```bash
   cp .env.example .env
   nano .env  # Укажите свои API_ID, API_HASH, GEMINI_API_KEY / ZAPRO_API_KEY
   ```

3. **Запустите через Docker Compose**:
   ```bash
   docker compose up -d --build
   ```

4. Откройте панель управления в браузере: `http://IP_СЕРВЕРА:5173`

---

### Вариант 2: Прямой запуск на сервере (Linux / VPS)

1. **Установите Python 3.10+ и Node.js 20+**:
   ```bash
   sudo apt update
   sudo apt install -y python3 python3-pip python3-venv nodejs npm git
   ```

2. **Клонируйте репозиторий и настройте окружение**:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd MyBotAi11-main
   cp .env.example .env
   ```

3. **Установите зависимости**:
   ```bash
   # Python
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt

   # Node.js
   npm install
   npm run build
   ```

4. **Запуск всех сервисов**:
   ```bash
   chmod +x start_all.sh
   ./start_all.sh
   ```

## 🔐 Безопасность

### Обновление авторизации и заказов (04.10.2026)

- Защищённые API требуют JWT cookie или Bearer-токен даже при локальном запуске.
- Быстрый вход использует полный номер телефона и персональный PIN. Общий `1234` отключён: войдите через Telegram и задайте PIN в профиле (4–12 цифр, кроме `1234`).
- PIN хранится как salted scrypt hash и не возвращается API. Существующие персональные PIN сохраняются при миграции; старое открытое поле очищается.
- Лимит быстрого входа — 5 запросов за 5 минут на IP и на номер. Лимит хранится в памяти одного процесса; для нескольких workers нужен общий storage.
- Backend при старте добавляет `users.pin_hash` и `orders.status`. Перед обновлением существующей SQLite автоматически сохраняется согласованная копия в `backups/`; ошибки новой миграции останавливают запуск. Резервные копии содержат чувствительные данные и исключены из Git/Docker context.
- Для PostgreSQL резервную копию нужно сделать средствами развёртывания до обновления. PostgreSQL-миграция пока не проверена на живой БД.
- Автономному боту нужна обновлённая схема: сначала запустите backend, затем бот, если запускаете его отдельно.

Офлайн-проверки входа, миграции и записи/смены статуса заказа:

```powershell
.\.venv\Scripts\python.exe -m unittest test_auth_orders -v
```

Проверки используют временные базы и не запускают Telegram, polling бота или lifespan приложения.

* Файлы сессий Telegram (`*.session`, `user_session.json`), база данных SQLite (`*.db`), медиафайлы (`temp_media/`) и файл `.env` находятся в `.gitignore` и **никогда не попадают в Git**.
* При развёртывании на новом сервере авторизация в Telegram происходит безопасно через веб-интерфейс (ввод номера и кода).

```powershell
npm run typecheck
npm run build
```

`typecheck` строго проверяет файлы приложения в корне, `pages/`, `components/`, `services/` и отдельно `vite.config.ts`. `build` сначала выполняет эту проверку и только затем собирает Vite bundle; ошибка типов останавливает сборку.

# Пилот фото товара через GPT Image 2

В редакторе `/dashboard/editor` появился отдельный блок фото по референсам.
Выберите фото взрослой виртуальной модели и 1–5 оригинальных фото товара
(по одному на расцветку), задайте фон/позу и качество, затем запустите генерацию.
Для каждой фотографии создаётся отдельный PNG 1024×1536 через выбранный API
`gpt-image-2`, `/v1/images/edits`. Модель получает оба изображения; отдельный
платный вызов для описания товара не нужен. `input_fidelity` не передаётся:
GPT Image 2 обрабатывает референсы с высокой точностью автоматически.

Личный Zapro/OpenAI ключ теперь можно сохранить в «Pro Профиль → Мой API для
изображений», затем перейти в меню «Фото по референсам». Ключ шифруется в отдельной
таблице `user_image_settings` по владельцу; исходящие адреса фиксированы для двух
провайдеров. Подробная инструкция: [ZAPRO_IMAGE_SETUP.md](ZAPRO_IMAGE_SETUP.md).
Личные настройки имеют приоритет; выключение или удаление личного ключа не включает
общий серверный ключ автоматически. Перезапустите backend после обновления кода:
новая таблица создаётся при `init_db` без изменения существующих колонок.

Старый общий режим OpenAI остаётся для аккаунтов без личных настроек.
Для него на сервере настройте `.env`, затем перезапустите backend:

```dotenv
OPENAI_IMAGE_API_KEY=ваш_отдельный_API_ключ_OpenAI
OPENAI_IMAGE_ENABLED=true
OPENAI_IMAGE_DAILY_LIMIT=20
```

Подписка ChatGPT Plus не оплачивает эти генерации. Ключ остаётся на сервере,
в браузер не возвращается. По умолчанию режим выключен. Каждый запуск платный;
число попыток ограничено дневным лимитом UTC (1–100 на пользователя).
В одном процессе допускается одна генерация одновременно; фото обрабатываются
последовательно, автоматические повторы отключены. После первой ошибки остальные
фото пропускаются. При таймауте провайдер мог списать стоимость запроса.

В течение 24 часов одного процесса повтор с тем же идентификатором возвращает
сохранённый ответ без новой генерации. UI сохраняет идентификатор, пока не изменены
входные данные. Лимиты и идентификаторы пока в памяти: перезапуск сбрасывает их,
несколько workers не координируются. Это пилот для одного backend-процесса,
а не постоянная серверная очередь. Не использовать его как строгий финансовый лимит;
лимиты расходов дополнительно задаются в аккаунте провайдера. Не закрывайте страницу
во время запроса; долгие запросы требуют соответствующего timeout reverse proxy.

Результаты хранятся в `private_image_previews/` вне публичного `/temp_media`,
скачиваются только после авторизации своего владельца. Файлы не удаляются
автоматически; папка исключена из Git и Docker build context. Загруженные оригиналы
не перезаписываются и на сервере не сохраняются. Telegram-публикация и обработка
донорских альбомов этим режимом не изменяются. Пока фото донора нужно скачать и
выбрать в редакторе вручную. Проверьте цвет, форму, фурнитуру, лицо и руки перед
ручной публикацией результатов; красивый результат не гарантирует точность товара.

Проверка без сетевых запросов и рабочей БД:
`.venv\Scripts\python.exe -m unittest test_auth_orders test_product_images -q`.

### Фоновый перенос донорских товаров на нашу модель

В «Магазине» и «Парсере» включите отдельную галочку GPT Image 2, сохраните 1–3
фото одной взрослой виртуальной модели, конкретное описание продаваемого предмета
и сцену. Сервер сам скачивает Telegram-альбом, передаёт все референсы генератору,
создаёт отдельное фото по каждому исходнику и публикует полный результат в целевые
каналы. Несколько каналов используют один набор генераций. Магазин сохраняет
наценки, артикулы и синхронизацию текста Mini App. Обычный перенос без галочки
продолжает работать. Если включён живой мониторинг, сервер ждёт новые альбомы
после первоначального импорта; вкладку можно закрыть.

Для первой проверки: 1 пост, мониторинг выключен, дневной лимит вмещает все фото
выбранного альбома. Один исходный ракурс/расцветка — одна попытка. Сначала проверьте
точность нового промпта в ручном пилоте. Статус задания и фотографии сохраняются;
после рестарта выполнение не возобновляется автоматически. Дневной счётчик фото
пока процессный. Требуется один backend-процесс, без нескольких workers.
Инструкция: [ZAPRO_IMAGE_SETUP.md](ZAPRO_IMAGE_SETUP.md).

Полная офлайн-проверка: `.venv\Scripts\python.exe -m unittest test_auth_orders test_product_images test_product_parser -q`.
